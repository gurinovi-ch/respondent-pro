# Дизайн-спецификация: режим инфокиоска (RESPONDENT.PRO)

**Дата:** 2026-09-28
**Статус:** утверждена (устно, по секциям)
**Область:** киоск-режим планшета. Автообновление приложения — отдельная задача после этой.

---

## 1. Цели и контекст

Приложение используется как стационарный информационный киоск для сбора отзывов клиентов. Планшет обслуживает посторонних посетителей, поэтому:

1. При загрузке системы приложение запускается автоматически и является **главным лаунчером**.
2. При сбое (crash, ANR, тихое убийство системой) приложение **перезапускается**.
3. Посторонний пользователь **не может управлять планшетом**: не выходит из приложения, не открывает чужие приложения, панели уведомлений и системных настроек (кроме разрешённого выхода), не сбрасывает и не удаляет приложение.
4. Полная блокировка включается через **Device Owner**, который выдаётся одним из двух способов, выбираемых администратором: ADB (с ПК) или QR-провижининг (со сбросом планшета). Способ выбора — в настройках приложения: статус DO + пошаговые инструкции под каждый способ.
5. Кнопка «Настройки Android» в настройках приложения сохраняется; во время открытых системных настроек поверх отображается плавающая кнопка возврата в приложение.
6. Киоск-режим **всегда включён** — переключателя нет.
7. Поддерживаемые версии: **Android 7–15** (minSdk 24 … targetSdk 35).

**Устройство для разработки/проб:** Lenovo TB-X606X, Android 10 (API 29), 0 аккаунтов, лаунчер `com.tblenovo.launcher`, DO не выдан.

**Хостинг APK:** GitHub Releases, стабильная ссылка `…/releases/latest/download/<имя>.apk` (нужна и для QR-провижининга, и позже — для автообновления).

## 2. Вне объёма

- Автообновление приложения (отдельная подсистема, отдельный spec).
- Управление системными настройками Lenovo (яркость, автосон системными средствами) — частично закрывается политиками DO.
- Многопользовательский режим, вторичные пользователи.
- Работа без лаунчер-замены (возможность «обычного» режима) — киоск постоянен.

## 3. Архитектура

Новый пакет `com.respondent.pro.kiosk`. Стиль проекта: Hilt, `@Singleton`, логирование через `Log` с тегами.

| Компонент | Тип | Ответственность |
|-----------|-----|-----------------|
| `KioskAdminReceiver` | `DeviceAdminReceiver` | Объявление в манифесте — цель выдачи DO. Логики нет. |
| `KioskManager` | `@Singleton` | Единая точка киоска: статус DO (`DevicePolicyManager.isDeviceOwnerApp`, `isLockTaskPermitted`), применение политик при старте, `startLockTask()`/`stopLockTask()`, флаг `isForeground` (обновляется из `MainActivity.onResume/onPause` — его читает `RestartReceiver`), подготовка payload QR. Нужен контекст приложения (`@ApplicationContext`). |
| `BootReceiver` | `BroadcastReceiver` | Только `BOOT_COMPLETED` (без `LOCKED_BOOT_COMPLETED` — receiver не directBootAware, упрощение: в DO-режиме экран блокировки отключён, система «пробуждается» сразу). БД/настройки не трогает — только запуск `MainActivity`. |
| `WatchdogScheduler` | object-планировщик | `AlarmManager` → `RestartReceiver` каждую ~1 мин (`setExactAndAllowWhileIdle`, API 23+). На API 31+: если `!canScheduleExactAlarms()` — откат на неточный `setAndAllowWhileIdle`. |
| `RestartReceiver` | `BroadcastReceiver` | Проверяет: процесс жив и есть resumed-активность → тишина; иначе → перезапуск `MainActivity` (NEW_TASK, singleTask). |
| `CrashHandler` | `Thread.UncaughtExceptionHandler` | Пишет крэш в файл (`filesDir/crash.log`), планирует перезапуск через AlarmManager (~1 сек), пробрасывает исключение дальше. Устанавливается в `RespondentApp.onCreate`. |
| `ProvisioningQr` | helper | Сборка JSON-payload Android Enterprise и генерация QR-изображения (ZXing). |

**Существующие файлы, которые меняются:**

| Файл | Изменение |
|------|-----------|
| `AndroidManifest.xml` | Категории `HOME`+`DEFAULT` у MainActivity; регистрация 3 receiver'ов; разрешения `RECEIVE_BOOT_COMPLETED`, `SCHEDULE_EXACT_ALARM`, `SYSTEM_ALERT_WINDOW`; `FileProvider` для share QR; `launchMode="singleTask"` |
| `MainActivity.kt` | Инициализация `KioskManager` в `onResume` (политики + `startLockTask()`), `FLAG_KEEP_SCREEN_ON` |
| `RespondentApp.kt` | Установка `CrashHandler` |
| `ui/screens/SettingsScreen.kt` | Новый Card «Инфокиоск»: статус + 2 spoiler-инструкции + генератор QR |
| `ui/i18n/AppStrings.kt` | Все новые строки ru/en (конвенция проекта) |
| `app/build.gradle.kts` | Зависимость ZXing (`journeyapps:zxing-android-embedded`) |
| `di/` | Не требуется — constructor injection, без модуля |

**База данных и настройки (DataStore) не меняются.** Поля Wi-Fi для QR — временное состояние UI, не персистится.

### Жизненный цикл

```
Загрузка системы → BootReceiver → MainActivity
  → KioskManager: политики DO (если выдан) + startLockTask()
Пользователь → приложение (лаунчер; кнопка Home = наш экран)
Сбой процесса → CrashHandler → AlarmManager (~1 сек) → MainActivity
Тихое убийство → Watchdog (~1 мин) → RestartReceiver → MainActivity
```

## 4. Совместимость Android 7–15 (API 24–35)

| Возможность | 24–28 | 29 | 31–32 | 33–35 |
|---|---|---|---|---|
| BootReceiver, автозапуск | ✅ | ✅ | ✅ | ✅ |
| Перезапуск из фона | свободно | ограничение bg-activity-start | то же | то же |
| Exact-alarm страж | ✅ | ✅ | нужен `SCHEDULE_EXACT_ALARM` | может быть отозван пользователем |
| Device Owner (ADB/QR) | ✅ | ✅ | ✅ | ✅ |
| Lock Task, `setStatusBarDisabled`, `setKeyguardDisabled` (API 23+) | ✅ | ✅ | ✅ | ✅ |

Правила:

1. Все системные вызовы — под `Build.VERSION.SDK_INT`-гардами.
2. `CrashHandler` — **первичный** механизм перезапуска (работает в момент сбоя, вне ограничений фона). Watchdog — вторичный.
3. Фоновый старт активности на API 29+ проверяется пробой (P2 ниже); при блокировке — цепочка резервов (см. «Риски»).
4. Команда `cmd package set-home-activity` существует с API 29; на Android 7–9 лаунчер выбирается системным диалогом при первом нажатии Home (в инструкции это описано).

## 5. Уровень 1: Device Owner выдан — полная блокировка

Политики применяет `KioskManager` при старте (все — API 23+):

| Политика | Эффект |
|----------|--------|
| `setLockTaskPackages(наш пакет)` | В Lock Task живём только мы; Home/Назад/Недавние не работают |
| `setStatusBarDisabled(true)` | Статусбар скрыт → панель уведомлений недоступна |
| `setKeyguardDisabled(true)` | Нет экрана блокировки — сразу наше приложение |
| `setUninstallBlocked(true)` | Нельзя удалить приложение |
| `DISALLOW_FACTORY_RESET` | Нельзя сброс до заводского |
| `DISALLOW_SAFE_BOOT` | Нельзя безопасный режим |
| `setMaximumTimeToLock(очень большое)` | Сон/блокировка экрана не включаются |
| `FLAG_KEEP_SCREEN_ON` в MainActivity | Экран не гаснет, пока приложение на экране |
| Скриншоты — **разрешены** (не выставляем `setScreenCaptureDisabled`) | Упрощает поддержку; чувствительных данных нет |

Вход в Lock Task: `onResume` MainActivity → `startLockTask()` (идемпотентен, при каждой активности — самовосстановление).

**USB-отладка и параметры разработчика остаются доступными** — «запечатывание» отладки не применяется. Настройки разработчика всегда можно открыть и изменить (через кнопку «Настройки Android» в нашем приложении): администратор и поддержка сохраняют полный сервисный доступ к планшету.

## 6. Выход в системные настройки

Путь: Настройки приложения (под PIN) → кнопка «Настройки Android».

```
1. KioskManager.stopLockTask()          — временно отпускаем
2. context.startActivity(ACTION_SETTINGS)
3. Оверлей-кнопка «◀ В RESPONDENT.PRO» — WindowManager, TYPE_APPLICATION_OVERLAY,
   справа внизу поверх кнопки «Назад»
4. Тап → MainActivity → onResume → startLockTask()
```

- **Оверлей-грант:** ADB-путь — команда `appops set … SYSTEM_ALERT_WINDOW allow` в инструкции; QR-путь — приложение при первом переходе в настройки обнаруживает отсутствие разрешения, открывает `ACTION_MANAGE_OVERLAY_PERMISSION` с пояснением (один тумблер). Если разрешения нет — оверлей не показывается, вместо него текстовая подсказка «Нажмите Home, чтобы вернуться».
- **Тип окна по версии:** API 24–25 → `TYPE_SYSTEM_ALERT`; API 26+ → `TYPE_APPLICATION_OVERLAY` (гард по `SDK_INT`).
- Страховка: мы — лаунчер → системная кнопка Home всегда возвращает в приложение.
- Кнопка «Назад» из настроек возвращает в приложение через стек задачи.
- Панель уведомлений остаётся скрытой (политика DO действует вне зависимости от Lock Task).

## 7. Уровень 2: Device Owner НЕ выдан — деградация

- Лаунчер + автозапуск + перезапуск + `FLAG_KEEP_SCREEN_ON` — работают всегда.
- Lock Task **не активируется** (система требует DO/whitelist); ошибок нет — просто пропуск.
- В настройках: статус «⚠️ Device Owner не выдан» + инструкции. Приложение не падает при потере DO в любой момент.

## 8. UI: блок «Инфокиоск» в настройках

Расположение: отдельный `Card` после существующего spoiler-блока инструкций и **перед** блоком «Способ отправки» («Способ отправки» остаётся последним, как утверждено ранее).

Содержимое:

1. **Статус** (обновляется при каждом открытии экрана):
   - ✅ `Device Owner выдан` (+ `Lock Task активен`)
   - ⚠️ `Device Owner не выдан — полная блокировка недоступна`
2. **Spoiler «Настройка через ADB (с ПК)»** — пошагово:
   - включить USB-отладку (О телефоне → 7 касаний на «Номере сборки»);
   - скачать APK с GitHub Releases (ссылка);
   - 4 команды (копирование по нажатию; имя ассета APK на GitHub Releases — фиксировано `RESPONDENT.PRO.apk`):
     ```
     adb install -r RESPONDENT.PRO.apk
     adb shell dpm set-device-owner com.respondent.pro/.kiosk.KioskAdminReceiver
     adb shell cmd package set-home-activity com.respondent.pro/.MainActivity   # Android 10+; ниже — выбрать лаунчер в диалоге
     adb shell appops set com.respondent.pro SYSTEM_ALERT_WINDOW allow
     ```
   - вернуться в приложение → статус ✅.
3. **Spoiler «Настройка через QR-код»** — пошагово:
   - генерация QR в приложении (поля: Wi-Fi SSID, пароль; кнопка «Показать QR»; сохранение/отправка изображения через `FileProvider` — показывают со второго устройства);
   - сброс планшета до заводского;
   - приветственный экран: Android 7–9 — 6 касаний; Android 10+ — иконка доступности → камера → сканирование;
   - планшет скачивает APK, становится DO, подключается к Wi-Fi;
   - после запуска: выбрать лаунчер (один раз), выдать оверлей-разрешение (переход из приложения).
4. **Генератор QR** (поля и кнопка — внутри spoiler). Payload (`ProvisioningQr`):
   ```json
   {
     "android.app.extra.PROVISIONING_DEVICE_ADMIN_COMPONENT_NAME": "com.respondent.pro/.kiosk.KioskAdminReceiver",
     "android.app.extra.PROVISIONING_DEVICE_ADMIN_PACKAGE_DOWNLOAD_LOCATION": "https://github.com/<owner>/<repo>/releases/latest/download/<apk-name>.apk",
     "android.app.extra.PROVISIONING_WIFI_SSID": "…",        // опционально
     "android.app.extra.PROVISIONING_WIFI_PASSWORD": "…",    // опционально
     "android.app.extra.PROVISIONING_SKIP_ENCRYPTION": true
   }
   ```
   Без Wi-Fi-полей — payload без сети, сеть выбирается в мастере вручную. `PROVISIONING_DEVICE_ADMIN_SIGNATURE_CHECKSUM` — харденинг, можно добавить позже.

Локализация: все строки — в `AppStrings.kt` (ru/en), как в остальном приложении.

## 9. Граничные случаи и обработка ошибок

| Ситуация | Поведение |
|----------|-----------|
| Попытка применить политики без DO | `try/catch` → лог → статус «не выдан», приложение работает |
| DO потерян (снят через ADB) | Статус меняется при следующем открытии настроек; Lock Task просто не активируется |
| Нет разрешения на оверлей | Оверлей не показывается → текстовая подсказка «Нажмите Home» + предложение выдать разрешение |
| Нет разрешения на exact alarm (API 31+) | Откат на неточный alarm; на API 24–28 не применяется |
| GitHub недоступен при QR-провижининге | Провижининг не удастся → запасной путь ADB (описан в инструкции) |
| Крэш в момент крэшей подряд | CrashHandler пишет в `crash.log` (с датой), перезапуск тем же механизмом; лог доступен при поддержке |
| Скриншот/перехват | Разрешены — осознанное решение |
| Первая установка: система спросит лаунчер | Один раз; для ADB-пути — команда `set-home-activity` (API 29+) убирает вопрос сразу |

## 10. Пробы (проверить на устройстве в первой итерации плана)

- **P1:** `dpm set-device-owner` на Lenovo (0 аккаунтов) — выдаётся ли без сброса.
- **P2:** Фоновый старт активности на API 29: crash-перезапуск и watchdog — что реально срабатывает; при блокировке — подключить резерв (foreground-service с `START_STICKY` и/или показ оверлея-«часов» до возврата).
- **P3:** `appops set … SYSTEM_ALERT_WINDOW allow` — корректное имя операции на Android 10.
- **P4:** `cmd package set-home-activity` на Lenovo — становится ли лаунчером по умолчанию.
- **P5:** Время перезапуска после `am crash` / `am kill` — соответствие чек-листу.

## 11. Риски

| Риск | Влияние | Митигация |
|------|---------|-----------|
| Один тестовый планшет (API 29) | Версии 7, 12–15 не проверены физически | Гарды `SDK_INT`; при доступе — эмуляторы API 24 и 35 |
| Android 10+ блокирует фоновый старт | Watchdog может не поднять активность | Резервная цепочка (P2), crash handler — первичный |
| Политики DO на Android 15 при targetSdk 35 | Возможны изменения поведения | Проба на эмуляторе API 35 |
| GitHub — единственный источник APK | Недоступность = нет QR-провижининга | ADB-путь как запасной |
| Lenovo-специфика лаунчера | `set-home-activity` может вести себя иначе | P4, запасной путь — системный диалог выбора |

## 12. Чек-лист приёмки

- [ ] Перезагрузка → приложение открывается само; после настройки — лаунчер по умолчанию
- [ ] `adb shell am crash` → перезапуск < 2 сек
- [ ] `adb shell am kill` → перезапуск ≤ ~1 мин
- [ ] DO выдан → Home/Назад/Недавние не выходят из приложения
- [ ] Панель уведомлений недоступна; экран не гаснет
- [ ] «Настройки Android» → оверлей-кнопка → возврат → Lock Task восстановлен
- [ ] Без DO → деградация: лаунчер/автозапуск работают, статус ⚠️, инструкции видны
- [ ] `dpm remove-device-owner` → приложение не падает, статус меняется
- [ ] QR-payload валиден (генерируется, формат JSON корректен)
- [ ] Все новые строки локализованы ru/en

## 13. Принятые решения (из обсуждения)

1. Два способа выдачи DO с выбором и инструкциями в настройках — решение заказчика.
2. Wi-Fi после блокировки — через системные настройки (п. 6), не отдельный UI в приложении.
3. Киоск всегда включён, переключателя нет.
4. Автообновление — отдельная задача.
5. Хостинг APK — GitHub Releases.
6. Генерация QR — внутри приложения (ZXing).
7. **USB-отладка и параметры разработчика остаются доступными** — «запечатывание» отладки не применяется (поддержка и сервисный доступ к планшету). Внесено по решению заказчика при самопроверке spec.

## 14. Параметры, заполняемые при реализации

- `github.com/<owner>/<repo>` — создаётся на шаге плана: `git init` + публичный репозиторий + GitHub Release с ассетом `RESPONDENT.PRO.apk`. Значение подставляется в QR-payload и в инструкцию ADB (ссылка «скачать APK»).
